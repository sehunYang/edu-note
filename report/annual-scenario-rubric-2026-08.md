# 물리교사·담임 연간 업무 시나리오 기반 UX 평가 (2026-08-02)

평가자 관점: **고등학교 물리 교과(2·3학년) 담당 + 담임 겸직 교사**.
평가 방법: 연간 업무를 시기별로 전개한 뒤, 각 업무를 이 앱으로 수행하는 동선을
모바일(390×844, `pointer: coarse` 실제 터치 에뮬레이션)과 데스크톱(1440×900,
루트 18px)에서 **실측**했다. 점수는 인상이 아니라 실측치에 근거한다.

1차 지필 범위 확정(수업 계획실 시험경계) → 시행 → 성적 기록 업로드 →

### 6~7월 — 1학기 마감
세특 초안(교실 → 세특 작성, 코워크 번들 내보내기) → 행특 누가기록 정리 →

### 8월 — 방학·2학기 준비 (**현재 시점**)
방학 판정 표시 확인 → 2학기 진도 계획 재수립 → 시간표 변경 반영(재동기화) →
3학년 수시 대비 생기부 사전 점검(인쇄실 → 학생별 점검).

### 9~10월 — 2학기 운영
3학년 수시 원서(생기부 최종 점검·인쇄) → 2차 상담주간 → 지필·수행 →
동아리 발표회 기록.

### 11~12월 — 마감 집중기
2학기 기말 → 성적 마감 → **생기부 전 영역 입력**(교과 세특·행특·자율·진로·
동아리) → NEIS 출결 마감 → 통계실 결손 점검 → 인쇄실 최종 검토·출력.

### 1~2월 — 학년 종료
정정·마감 → 백업 내보내기(JSON) → 차년도 세팅 준비.

## 3. 평가 결과

| 축 | 모바일 | 데스크톱 |
|----|--------|----------|
| 목적성 및 문제 해결 | **4** | **5** |
| 일관성 | **3** | **4** |
| 접근성 | **2** | **4** |

### 3-1. 목적성 및 문제 해결 — 모바일 4 / 데스크톱 5

연간 업무 전 항목이 대응 화면을 갖는다. 시나리오에서 미대응으로 남는 업무가
없었다. 특히 넛지(행특·관찰·미제출 신고서)가 홈/오늘의 학교에서 **딥링크로
사전선택까지 넘겨주는** 설계는 "퇴근 후 폰으로 밀린 기록 처리" 맥락에 정확히
맞는다. 오늘의 학교의 출결 빠른 입력 카드도 조회 시간 동선을 한 화면으로 줄인다.

감점 사유(모바일 −1): **인쇄실이 홈에서 도달 불가.** 사이드바·하단 탭바
"더보기"에는 있으나 홈 대시보드 실 카드는 6개뿐이라 9개 공간 중 인쇄실만
빠져 있다. 12월 마감기·9월 수시 점검기에 쓰는 실이 홈에서 안 보인다.

### 3-2. 일관성 — 모바일 3 / 데스크톱 4

같은 성격의 "화면 내 구획 전환"이 서로 다른 4가지 시각 표현으로 구현돼 있다.

| 위치 | 표현 |
|------|------|
| 교실·담임·동아리 실 탭 | `rounded-full` 알약 (`TabNav`, min-h-11) |
| 출결 5개 뷰 | `border-b-2` 밑줄 |
| 생기부 작성 3개 뷰 | `border-b` 밑줄 (굵기 다름) |
| 학기 선택 / 인쇄실 범위 | `rounded-md` 세그먼트 |

세그먼트 2곳은 서로 일치하나, 밑줄 2곳이 굵기가 달라 같은 패턴의 미묘한
변형으로 남았고, 실 탭과도 계열이 다르다. 데스크톱은 사이드바가 상시 위계를
잡아 주어 체감이 덜하다(−1), 모바일은 이 인페이지 탭이 유일한 이동 수단이라
화면마다 다른 모양을 학습해야 한다(−2).

### 3-3. 접근성 — 모바일 2 / 데스크톱 4

**(a) 폼 입력 폰트가 전 화면 16px 미만 — 모바일 2점의 주된 근거**

실측(터치 에뮬레이션, 입력 필드 중 16px 미만 비율):

| 화면 | 비율 |
|------|------|
| `/setting/courses` | 150 / 150 |
| `/clubroom/assign` | 118 / 118 |
| `/classroom/grades` | 103 / 103 |
| `/homeroom/notice` | 98 / 98 |
| `/setting/calendar` | 28 / 28 (일부 12px) |
| `/homeroom/attendance` | 13 / 13 |
| `/today` | 12 / 12 |
| `/classroom/observations` | 5 / 5 |

**모든 화면의 모든 입력 필드가 12~14px다.** iOS Safari는 포커스 대상
input/select/textarea의 폰트가 16px 미만이면 페이지를 자동 확대한다. 조회 시간에
출결을 넣으려 셀렉트를 탭할 때마다 화면이 확대되고, 교사는 다음 학생을
누르려고 매번 손으로 축소해야 한다. 시나리오상 최빈 모바일 과업에 매 입력마다
걸리는 마찰이다.

**(b) WCAG 2.2 SC 2.5.8(AA, 24×24) 위반 링크 8개**

문장 속 인라인 링크가 아니라 카드의 독립 액션인데도 24px 미만이다.

| 화면 | 링크 | 높이 |
|------|------|------|
| `/` | 행특 쓰기 → | 20px |
| `/` | 확인하기 → | 20px |
| `/` | 전체 보기(캘린더 등) → | 16px |
| `/today` | 행특 쓰기 → | 20px |
| `/today` | 확인하기 → | 20px |
| `/today` | 출결 관리 전체 → | **14px** |
| `/today` | 미제출 신고서 | 16px |
| `/today` | 시수 | 16px |

하필 **넛지의 실행 링크**들이다. 넛지 설계의 목적(밀린 기록을 즉시 처리)이
가장 작은 터치 타깃에 걸려 있다. 데스크톱에서도 16~20px라 양 환경 공통 위반이다.

**(c) 44px 미만(위반은 아니나 HIG 미달)**
출결 뷰 탭 5개 38px, 세팅 스테퍼 5개 37px, 학기 링크 25px, 백업 29px.
출결 뷰 탭은 모바일 최빈 화면이라 개선 가치가 있다.

**검증하여 기각한 의심 항목**: 체크박스 원소 자체는 24px지만
`label:has(> input[type=checkbox])` 규칙이 감싼 label을 44px로 만들고 있어
실제 히트 영역은 44px다(`/homeroom/notice` 138개, `/clubroom/assign` 126개
컨트롤 전수 재측정 결과 44px 미만 0개). **결함 아님.**

**데스크톱이 4점인 이유**: 가로 스크롤 0, 타입 스케일 정상 동작
(H1 27 / H2 21 / H3 19 / 본문 17), 컨트롤 바닥 2rem 적용 확인.
감점은 위 (b)가 데스크톱에도 걸리기 때문.

## 4. 조치 (점수 미흡분 대응)

| # | 대상 | 축 | 조치 |
|---|------|----|------|
| A | 전 화면 입력 필드 | 접근성 모바일 2 | coarse 포인터에서 폰트 16px 바닥 |
| B | 넛지·위젯 링크 8개 | 접근성 양쪽 | `.tap-link` 유틸(24/44px 2단 바닥) |
| C | 출결 뷰 탭 | 접근성 모바일 | 38 → 44px |
| D | 밑줄 탭 2종 | 일관성 | `UnderlineTabs` 공용 컴포넌트로 통일 |
| E | 홈 대시보드 | 목적성 모바일 | 인쇄실 카드 추가(9공간 전부 도달) |

### 구현 메모 — 특정도 함정 (A)

첫 시도는 `select, textarea, input:not(...)` 를 `@layer base` 에 넣었는데
**셀렉트·텍스트에어리어만 14px 로 남았다.** Tailwind 3 의 `@layer` 는 네이티브
캐스케이드 레이어가 아니라 PostCSS 지시자라 레이어 순서가 아니라 특정도로
갈린다 — `select`(0,0,1)는 `.text-sm`(0,1,0)에 지고, `input:not([type="hidden"])`
은 (0,1,1)이라 우연히 이기고 있었다. `:not([hidden])` 을 붙여 셋 다 (0,1,1)로
맞춰 해결했다. (실측이 없었으면 "고쳤다"고 넘어갔을 부분이다.)

### 5-3. 터치 타깃 44px 미만 (모바일)

| 화면 | 조치 전 | 조치 후 |
|------|---------|---------|
| `/homeroom/attendance` | 5 (뷰 탭 38px) | **0** |
| `/today` | 5 | **0** |
| `/` | 4 | 1 (백업 내보내기 29px) |

남긴 1건은 학년말에 한 번 쓰는 백업 링크이고 SC 2.5.8(24px)은 통과한다.
세팅실 스테퍼 5개(37px)·학기 링크(25px)도 같은 이유로 유지했다 — 전부 24px
기준은 넘고, 세팅실은 3월에 한 번 지나가는 화면이다.

### 5-5. 조치 후 점수

| 축 | 모바일 | 데스크톱 |
|----|--------|----------|
| 목적성 및 문제 해결 | 4 → **5** | 5 |

일관성 모바일이 5가 아닌 이유: 인페이지 전환 계열이 아직 3종(실 탭 알약 /

정보 구조상 층위가 달라(실 이동 / 뷰 전환 / 값 선택) 이번 범위에서 제외했다.

접근성 모바일이 5가 아닌 이유: 5-3의 잔여 항목(24px는 통과, 44px 미만 소수).
