# 구글 캘린더 동기화 — 직접 설정 가이드 (사용자 수행)

오늘의 학교 캘린더에 추가한 개인 일정을 **내 구글 캘린더에 자동으로 넣는 기능**을 쓰기
위해, 코드 배포와 별개로 **선생님이 직접 해야 하는 설정**을 모았습니다.

- 총 소요: **약 15분** (①~③ 구글 클라우드 10분 + ④ 환경변수 4분 + ⑤ 연결 1분)
- ①~④는 **기능 배포 전에 미리 해두어도 됩니다**(순서: ① → ② → ③ → ④ 권장).
  ⑤만 배포 후에 하면 됩니다.
- 어려운 개념은 몰라도 됩니다. 화면의 버튼 이름 그대로 따라가면 됩니다.

> 배경 계획서: `.omc/plans/google-calendar-sync-plan.md` (설계·보안 근거는 여기 참고)

## 준비물 확인 (1분)

아래 두 가지에 로그인할 수 있으면 준비 끝입니다.

| 필요한 것 | 어디서 쓰나 |
|---|---|
| 구글 계정 (오늘의 학교 로그인에 쓰는 그 계정) | ①~③, ⑤ |
| Vercel 계정 (edu-note 프로젝트가 있는 곳) | ④ |

## ① Google Calendar API 켜기 (3분)

**왜 필요한가**: 우리 앱이 구글 캘린더에 일정을 "써넣으려면" 구글 쪽에서 이 API 스위치를
켜두어야 합니다. 한 번만 켜면 됩니다.

1. 브라우저에서 https://console.cloud.google.com 접속 → 구글 계정으로 로그인.
2. 화면 **왼쪽 상단**의 프로젝트 이름(드롭다운)을 클릭 → **Supabase 구글 로그인을 만들 때
   썼던 프로젝트**를 선택합니다.
   > 💡 어떤 프로젝트인지 기억나지 않으면: Supabase 대시보드 → **Authentication →
   > Providers → Google** 에 적힌 **Client ID의 맨 앞 숫자 덩어리**가 프로젝트 번호입니다.
   > 드롭다운 목록에서 그 번호와 같은 프로젝트를 고르면 됩니다.
3. 왼쪽 햄버거(≡) 메뉴 → **API 및 서비스 → 라이브러리** 클릭.
4. 검색창에 `Google Calendar API` 입력 → 검색 결과에서 **Google Calendar API** 클릭.
5. 파란색 **사용(Enable)** 버튼 클릭.
   - 이미 "API 사용 설정됨 / 관리(Manage)"라고 보이면 이미 켜져 있는 것입니다. 그대로
     다음 단계로 가세요.

✅ 완료 확인: 버튼이 **관리(Manage)** 로 바뀌어 있으면 성공.

## ② 동의 화면에 캘린더 권한 추가 (3분)

**왜 필요한가**: 나중에 ⑤에서 "이 앱이 내 캘린더 일정을 수정해도 됩니다"라고 동의하게
되는데, 그 동의 화면에 캘린더 권한 항목을 미리 등록해 두는 작업입니다.

1. 같은 구글 클라우드 화면에서 **API 및 서비스 → OAuth 동의 화면** 클릭.
   > 💡 최근 UI에서는 이름이 바뀌었습니다. 왼쪽 메뉴에 **"데이터 액세스(Data Access)"**
   > 가 보이면 그걸 클릭하세요 — 같은 화면입니다.
2. **범위 추가 또는 삭제(Add or remove scopes)** 버튼 클릭 → 오른쪽 패널이 열립니다.
3. 패널의 필터(검색) 칸에 `calendar.events` 입력.
4. 목록에서 API가 **Google Calendar API**, 범위가 `…/auth/calendar.events`
   (설명: "캘린더에서 액세스할 수 있는 모든 일정 보기 및 수정") 인 행의 **체크박스** 선택.
   - 비슷한 이름(`calendar`, `calendar.events.readonly` 등)이 여럿 보여도 **정확히
     `…/auth/calendar.events` 하나만** 체크하면 됩니다.
5. 패널 하단 **업데이트(Update)** 클릭 → 원래 화면으로 돌아오면 **저장(Save)** 클릭.

✅ 완료 확인: "민감한 범위(Sensitive scopes)" 표에 `…/auth/calendar.events` 가 보이면 성공.

## ③ 앱을 '프로덕션'으로 게시 (2분) — ⚠ 가장 중요한 단계

**왜 필요한가**: 구글은 동의 화면이 **'테스트' 상태인 앱에는 연결 수명을 7일로 제한**
합니다. 이대로 두면 **매주 "구글 재연결 필요"가 떠서 다시 연결해야** 합니다.
'프로덕션'으로 게시하면 한 번 연결로 계속 유지됩니다.

1. **API 및 서비스 → OAuth 동의 화면**으로 이동.
   > 💡 새 UI에서는 왼쪽 메뉴의 **"대상(Audience)"** 을 클릭하세요.
2. **게시 상태(Publishing status)** 를 확인합니다.
   - 이미 **프로덕션(In production)** 이면 → 이 단계는 끝. ④로 가세요.
   - **테스트(Testing)** 라면 → **앱 게시(Publish app)** 버튼 클릭 → 확인 팝업에서 **확인**.
3. "검증이 필요할 수 있다"는 안내가 보여도 **검증 심사는 신청하지 않아도 됩니다.**
   선생님 본인만 쓰는 앱이라 심사 없이도 동작합니다. 대신 ⑤에서 연결할 때 아래 경고
   화면이 **한 번** 나옵니다:

   > **"Google에서 확인하지 않은 앱"** 화면이 나오면:
   > 왼쪽 아래 **고급(Advanced)** 클릭 → **(앱 이름)(안전하지 않음)으로 이동** 클릭.
   > 본인이 만든 본인 전용 앱이므로 안전합니다. 이후에는 다시 나오지 않습니다.

✅ 완료 확인: 게시 상태가 **프로덕션(In production)** 으로 표시되면 성공.

## ④ 환경변수 3개 등록 (4분) — Vercel + 로컬

**왜 필요한가**: 서버가 구글과 통신할 때 쓰는 열쇠 3개입니다. 코드에 넣지 않고
환경변수로만 보관합니다.

### ④-1. 값 3개 준비

**(a) `GOOGLE_CLIENT_ID` 와 `GOOGLE_CLIENT_SECRET`**

1. 구글 클라우드 → **API 및 서비스 → 사용자 인증 정보(Credentials)**.
2. **OAuth 2.0 클라이언트 ID** 목록에서 항목(보통 1개) 클릭.
3. 오른쪽(또는 상단)에 보이는 **클라이언트 ID** 와 **클라이언트 보안 비밀번호(Client
   secret)** 를 각각 복사해 메모장에 잠시 붙여둡니다.
   > 💡 이 두 값은 Supabase 대시보드 → Authentication → Providers → Google 에 입력돼
   > 있는 값과 **같아야** 합니다. 만약 다르면(클라이언트가 여러 개면) **Supabase에
   > 입력된 쪽**을 기준으로 쓰세요.

**(b) `GOOGLE_TOKEN_ENC_KEY`** (토큰 암호화 열쇠 — 새로 만듭니다)

1. 프로젝트 폴더에서 터미널을 열고 아래 한 줄을 실행합니다:
   ```
   node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
   ```
2. 출력된 한 줄(무작위 문자열)을 복사합니다.
3. ⚠ **이 값은 비밀번호 관리자 등 안전한 곳에 꼭 백업하세요.**
   잃어버리면 큰일이 나는 건 아니지만, 나중에 캘린더를 **재연결 1회** 해야 합니다.

### ④-2. Vercel에 등록

1. https://vercel.com → 로그인 → **edu-note** 프로젝트 클릭.
2. 상단 **Settings → Environment Variables**.
3. 아래 3개를 **하나씩** 추가합니다. 각각 Key/Value 입력 후, **Environment 는
   Production · Preview · Development 세 개 모두 체크** → **Save**:

   | Key | Value |
   |---|---|
   | `GOOGLE_CLIENT_ID` | ④-1(a)에서 복사한 클라이언트 ID |
   | `GOOGLE_CLIENT_SECRET` | ④-1(a)에서 복사한 클라이언트 보안 비밀번호 |
   | `GOOGLE_TOKEN_ENC_KEY` | ④-1(b)에서 만든 무작위 문자열 |

4. 환경변수는 **다음 배포부터** 반영됩니다. 기능 코드가 배포될 때 자동으로 함께
   반영되므로 따로 재배포할 필요는 없습니다.
   (만약 기능 배포 **이후에** 이 단계를 했다면: **Deployments → 최신 배포 → ⋯ →
   Redeploy** 한 번 눌러주세요.)

### ④-3. 로컬(.env.local)에도 등록 (로컬 개발·테스트용)

프로젝트 폴더의 `.env.local` 파일을 열어 **맨 아래**에 3줄을 추가합니다
(따옴표 없이, `=` 양옆 공백 없이):

```
GOOGLE_CLIENT_ID=복사한값
GOOGLE_CLIENT_SECRET=복사한값
GOOGLE_TOKEN_ENC_KEY=복사한값
```

✅ 완료 확인: Vercel Environment Variables 목록에 3개가 보이고, `.env.local` 에 3줄이
추가되어 있으면 성공.

## ⑤ 앱에서 연결하기 (1분) — 기능 배포 후 딱 1회

1. 오늘의 학교 앱에 로그인 → **세팅실 → 프로필**로 이동.
2. **"구글 캘린더 연결"** 버튼 클릭.
3. 구글 화면이 열리면 계정 선택 → 캘린더 권한 **허용(Allow)**.
   - "Google에서 확인하지 않은 앱" 경고가 나오면 ③의 방법대로
     **고급 → (앱 이름)(안전하지 않음)으로 이동**.
4. 프로필 화면으로 돌아와 **"연결됨"** 표시를 확인합니다.
5. 동작 확인: 오늘의 학교 캘린더에서 날짜 하나를 눌러 일정을 추가 →
   https://calendar.google.com 을 열어 같은 날짜에 일정이 생겼는지 확인. 보이면 끝! 🎉

## 자주 묻는 질문 / 문제 해결

**Q. "구글 재연결 필요" 표시가 떴어요.**
프로필의 **"구글 캘린더 연결"** 버튼을 다시 누르면 됩니다(1분). 원인은 대개 두 가지:
- ③을 건너뛰어 앱이 '테스트' 상태 → 7일마다 만료됩니다. ③을 수행하면 재발하지 않습니다.
- 구글 계정 보안 설정 변경(비밀번호 변경 등)으로 구글이 연결을 끊은 경우 — 재연결이면 충분.

**Q. `GOOGLE_TOKEN_ENC_KEY` 를 잃어버렸거나 바꿨어요.**
데이터가 사라지지는 않습니다. 새 키를 만들어(④-1(b)) Vercel·로컬에 다시 등록하고
재배포한 뒤, 프로필에서 **재연결 1회**만 해주면 정상 복구됩니다.

**Q. 구글 캘린더에서 일정을 지웠는데 앱에는 남아 있어요.**
정상입니다. 동기화는 **앱 → 구글 한 방향**입니다. 구글 쪽에서 지우거나 고친 내용은
앱으로 돌아오지 않으며, 앱에서 그 일정을 다시 수정하면 앱 내용대로 구글에 다시
생성/덮어쓰기 됩니다. **일정 관리는 항상 오늘의 학교에서** 하는 것을 권장합니다.

**Q. 앱에서 일정을 지웠는데 구글에 일정이 남아 있어요.**
드물게 삭제 순간 네트워크 오류가 나면 구글 쪽 일정이 남을 수 있습니다(앱 삭제는 항상
성공). 이 경우 구글 캘린더에서 그 일정만 수동으로 지워주면 됩니다.

**Q. 일정을 추가했는데 구글에 안 보여요.**
1. 프로필 카드에 오류 메시지("구글 동기화 오류")가 있는지 확인 — 있으면 내용에 따라
   재연결(위 첫 번째 Q) 또는 잠시 후 그 일정을 한 번 수정·저장(자동 재시도)해 보세요.
2. 구글 캘린더 화면에서 해당 날짜로 이동했는지, 왼쪽 캘린더 목록에서 기본 캘린더가
   체크되어 있는지 확인하세요.

**Q. 연결을 끊고 싶어요.**
프로필 → **연결 해제**. 이후 추가하는 일정은 구글로 보내지 않습니다. 이미 넘어간
일정은 구글에 그대로 남습니다(필요하면 구글에서 수동 삭제).

**Q. 학생들에게도 내 개인 일정이 보이게 되나요?**
아니요. 이 기능이 다루는 일정(오늘의 학교 개인 일정)은 원래부터 학생 공개 페이지에
노출되지 않는 데이터이며, 이번 변경도 그 원칙을 그대로 유지합니다.
