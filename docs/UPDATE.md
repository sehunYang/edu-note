# 업데이트

**대부분의 업데이트는 저절로 반영됩니다.** 매일 새벽에 새 버전이 있는지 확인하고,
있으면 알아서 받아서 배포합니다. 선생님은 아무것도 하지 않으셔도 됩니다.

딱 한 경우만 예외입니다 — **데이터가 사라질 수 있는 변경**이 포함되면 자동으로
반영하지 않고 확인을 요청합니다.

## 먼저 · 자동 확인 켜기 (한 번만)

Vercel 이 저장소를 복사할 때 **`.github` 폴더는 가져오지 못합니다**(GitHub 이 그
폴더의 파일 푸시에 별도 권한을 요구합니다). 그래서 처음 한 번만 파일을 만들어야 합니다.

앱에서 **세팅실 → 시스템 상태 → 자동 업데이트 확인 → `GitHub 에서 켜기`** →
열린 편집기에서 **Commit changes**.

그다음 저장소 **Settings → Actions → General** 에서
**Allow GitHub Actions to create and approve pull requests** 체크.
(데이터가 바뀌는 업데이트일 때 확인 요청을 만드는 데 씁니다.)

한 번만 하면 그 뒤로는 자동입니다.

## 언제 확인하나요

**매일 새벽 5시**에 새 버전이 있는지 확인합니다. 있으면 그대로 반영하고 배포합니다.

원본이 선생님 저장소로 먼저 알릴 수는 없어서(그게 정상입니다) 이렇게 주기적으로
확인하는 방식입니다. 급하면 저장소 **Actions → 업데이트 확인 → Run workflow** 로
즉시 당겨올 수 있습니다.

앱 안 **세팅실 → 시스템 상태**에서 현재 버전을 볼 수 있습니다.

> ⚠️ **내 저장소에서 실행해야 합니다.** 원본(sehunYang/edu-note)에서 실행하면
> "여기는 원본 저장소입니다"라는 안내만 남기고 아무 일도 하지 않습니다.
> 주소창이 `github.com/내아이디/edu-note` 인지 확인하세요.

## 왜 대부분은 그냥 맡겨도 되나요

안전장치가 두 겹 있습니다.

1. **빌드가 실패하면 새 버전이 올라가지 않습니다.** Vercel 은 실패한 빌드를 배포하지
   않으므로, 문제가 있으면 기존 버전이 그대로 돕니다.
2. **데이터베이스 변경이 실패해도 빌드 실패로 처리됩니다.** 스키마가 어중간한 상태로
   남은 채 새 코드가 올라가는 일이 없습니다.

그래서 되돌릴 수 없는 위험은 사실상 하나, **데이터가 사라지는 변경**뿐입니다.
그것만 선생님께 여쭙고 나머지는 자동으로 갑니다.

## 데이터가 바뀌는 업데이트일 때

저장소 **Pull requests** 탭에 확인 요청이 올라오고, 본문에 무엇이 바뀌는지와
경고가 적혀 있습니다.

1. **머지 전에** 앱의 세팅실 → 시스템 상태 → **백업 내려받기**
2. 내용을 확인하고 **Merge pull request**

## 업데이트가 어떤 모습인지

Vercel 이 저장소를 만들 때 원본의 git 이력을 물려받지 않습니다. 그래서 업데이트 PR 은
"몇 개 커밋을 합친다"가 아니라 **원본의 현재 내용을 그대로 가져오는** 형태입니다.
diff 에는 실제로 달라진 파일만 나오므로 읽는 데는 차이가 없습니다.

의미 있는 차이는 하나입니다 — **코드를 직접 고치셨다면 그 수정이 되돌아갑니다.**
diff 에 그 파일이 보이면 머지 전에 확인해 주세요. 고친 적이 없다면 신경 쓰지 않으셔도
됩니다.

---

## 직접 확인하고 싶을 때 (기다리지 않고)

저장소 → **Actions** → 왼쪽에서 `업데이트 확인` → **Run workflow**

로그에서 이렇게 읽습니다.

| 로그 | 뜻 |
|---|---|
| `확인 대상: 내아이디/edu-note` | 제대로 된 곳에서 실행됨 |
| `여기는 원본 저장소입니다` | ⚠️ 원본에서 실행함 — 내 저장소로 가세요 |
| `원본에 이 저장소에 없는 커밋: N개` | 새 버전 N개 발견 |
| `이미 최신입니다` | 업데이트 없음 (정상) |

## PR이 안 만들어질 때

저장소 **Settings → Actions → General** 에서
**Allow GitHub Actions to create and approve pull requests** 를 켜 주세요(한 번만).

이 설정이 꺼져 있으면 브랜치(`update/날짜`)까지만 만들어집니다.
그 경우 저장소 상단의 **Compare & pull request** 버튼으로 직접 열면 됩니다.

## 충돌이 났을 때

코드를 직접 고치신 적이 있으면 자동 병합이 실패하고 **Issue**가 하나 생깁니다.
그 내용을 그대로 복사해 [원본 저장소 Issues](https://github.com/sehunYang/edu-note/issues)에
남겨 주시면 도와드리겠습니다.

## 업데이트를 안 받고 싶다면

저장소 → **Actions** 탭 → `업데이트 확인` 워크플로 → **Disable workflow**.

다만 학교 시스템(나이스·컴시간)의 형식이 바뀌면 앱이 멈출 수 있고,
그 수정도 업데이트로 전달되므로 켜 두시길 권합니다.
